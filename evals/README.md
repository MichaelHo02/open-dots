# Open Dots WebMCP evals

Evaluations for the `document.modelContext` tools, following
[Chrome's WebMCP eval guidance](https://developer.chrome.com/docs/ai/webmcp/evals)
and the format used by [GoogleChromeLabs/webmcp-tools](https://github.com/GoogleChromeLabs/webmcp-tools).

Chrome splits WebMCP testing into three layers. This directory covers all three:

| Layer | What it checks | How to run |
| --- | --- | --- |
| 1. Tool-in-isolation (schema/description) | Can a model understand each tool from its name, description, and `inputSchema`? | `npm run test:webmcp` |
| 2. Deterministic tests | Does tool logic validate input and report errors gracefully (never throw)? | `npm run test:webmcp` |
| 3. Probabilistic + browser | Does the LLM pick the right tool with the right args? | `npx webmcp-evals browser …` |

## Files

- **`open-dots.evals.json`** — the eval suite in Chrome's format: an array of
  `{ name, messages, expectedCall }` cases. `expectedCall` uses the matcher
  operators (`$any`, `$type`, `$contains`, `$gte`, `$pattern`, …) so a single
  suite works across the CLI's `local`, `browser`, and `smoke` modes. The last
  case is an end-to-end journey using an `ordered` group.
- **`schema.json`** — a generated dump of every registered tool's
  `name`/`description`/`inputSchema`, consumable by `webmcp-evals local`.
  Regenerated by `npm run test:webmcp`; do not edit by hand.

## Layers 1 & 2 — deterministic runner (CI-friendly)

```bash
npm run test:webmcp
```

`scripts/webmcp-evals.ts` runs with no browser, no API key, and no network. It:

1. Builds the live tool set (`buildFilmTools`) and lints each tool — valid
   name, non-trivial description, `inputSchema.type === "object"`, `required`
   keys that exist in `properties`, and a boolean `annotations.readOnlyHint`.
2. Executes deterministic paths with no DOM: `get_pixel_art_guide` returns
   content; every tool with required args returns `isError` (never throws) when
   called with missing args; and `get_film` surfaces an internal runtime throw
   as a structured `isError` (proving the `withSafeExecute` backstop).
3. Verifies the eval suite only references real `functionName`s and declared
   argument properties, and that every tool is covered by at least one case.
4. Emits `schema.json`.

Exit code is non-zero if any check fails, so it drops into CI directly.

## Layer 3 — probabilistic / browser (live model)

Uses the official CLI against a running page. Requires Chrome (Canary for the
WebMCP flag) and a model backend/API key.

```bash
# LLM tool-selection eval against the deployed site
npx webmcp-evals browser -u https://pixel-film-studio.vercel.app -e evals/open-dots.evals.json --open

# Deterministic smoke run (executes expectedCall directly, no LLM/API key)
npx webmcp-evals smoke -u http://localhost:3000 -e evals/open-dots.evals.json -v
```

> Note: `smoke` resolves matcher constraints to sample values, so cases whose
> arguments are model-dependent (`colors`, asset `id`s) are best exercised via
> `browser` mode with a live model.
